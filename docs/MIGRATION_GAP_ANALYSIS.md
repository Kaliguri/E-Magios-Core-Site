# Анализ миграции: Legacy → React. Конспект фич и пробелы

> Составлено на ветке `migration/phases-0-1-2`, дата 2026-06-03.
> Цель: зафиксировать ВСЕ фичи legacy и новой версии, найти расхождения и составить
> план полноценной миграции. Используется как чек-лист для дальнейшей работы.

Legacy = ванильный сайт в корне репозитория (`*.html` + `*.js`, Firebase 8.x compat).
React = `node_modules/@e-magios/web/src` (Vite + React Router + FSD, Firebase 9 modular).

---

## 1. Полный список фич LEGACY

### 1.1. Навигация / каркас (`common.js`, `sidebar.js`, `books.js`, `scroll.js`)
- Сайдбар, собираемый из `BOOKS` (книги + главы), секции: **Главная / Новости / Профиль / Лобби**, **Книги** (сворачиваемые), **Инструменты** (Редактор / БД / Дашборд).
- Раскрытие/сворачивание книг (`toggleBook`), подсветка активной главы.
- Кнопка «Наверх» (`scroll.js`) на всех страницах.
- Единый экран загрузки (`page-loader`) для профиля/редактора/лобби, убирает «мигание» авторизации.

### 1.2. Доступ и авторизация (`access.js`, `auth.js`, `config.js`)
- **Парольная защита книг** через `localStorage` (`PASSWORD_KEY`), модалка ввода пароля, кнопка сброса 🔓 (hover-зона).
- В legacy `BOOKS` **все книги `locked: true`** (включая PHB).
- **Google-авторизация** (Firebase Auth) — гейт для редактора персонажей и лобби; модалка «Требуется вход».
- Универсальный слушатель `initDiceAuth` для виджета кубов.

### 1.3. Книги правил (`phb.html`, `spellbook.html`, `master.html`, `craftbook.html`, `rumors.html` + папки глав)
- 5 книг: PHB (19 глав), Spellbook (8), Master's Handbook (6), Craftbook (3), Rumors (2).
- Статические HTML-главы с якорями и перекрёстными ссылками.

### 1.4. Новости / changelog (`news.html`, `news.js`)
- 5 записей changelog, новейшая раскрыта.
- Каждая запись: краткое описание, **«Новый функционал на сайте»** (список + ссылки «См. также»), **«Новые объекты в базе данных»**, **«Статистика после обновления»**.
- **Динамическое разрешение объектов**: грузит `data/*.json` (14 коллекций) и резолвит id/имена в кликабельные ссылки на БД (`db.html?spell=…`, `?openTab=…`). Поддержка `'all'` и фиксированных снапшот-списков (`INITIAL_SPELL_NAMES`, `DB_UPDATE_*`).
- Подсчёт статистики (символы контента, число глав, объекты по коллекциям) — частично из данных, частично из зафиксированных констант (`LATEST_STATS_SNAPSHOT`).

### 1.5. База данных (`db.html`, `db.js` ~5k строк, `schema.js`)
- **14 вкладок**: заклинания, школы, эффекты, архетипы, базовые действия, навыки, типы действий, боевые компоненты, ремесленные компоненты, профессии, специализации, типы рецептов, рецепты, «основы системы» (basics).
- Источник данных: **локальные `data/*.json`** через `getDataUrl()`.
- Таблицы со схемой колонок/фильтров из `schema.js` (единое место правок).
- Поиск, сортировка по колонкам, фильтры (применить/отмена/очистить), сохранение фильтров и поиска в `sessionStorage`.
- **Поп-апы (detail modal)** с богатой версткой по типу сущности.
- **Undo/Redo (Назад/Вперёд)** внутри поп-апа, восстановление открытого объекта по URL/сессии (`restoreDbDetailOnLoad`, `?spell=…`).
- **Перекрёстные ссылки внутри описаний**: `linkifySchoolText`, `linkifySchoolProperty`, `linkifyDistance`, `linkifyResources` — клики открывают связанные объекты.
- **Кликабельные формулы бросков** в описаниях (`linkifyDiceExpressions`) — открывают глобальный виджет кубов и сразу бросают.
- Авто-кнопки в поп-апах заклинаний (Аркана / Попадание / Наложение) с подстановкой бонуса из описания.
- `?openTab=` для прямой ссылки на вкладку.

### 1.6. Глобальный виджет кубов (`common.js`, ~1.2k строк этого функционала)
- **Плавающий виджет кубов на ВСЕХ страницах** (`createDiceRollerUI`).
- История бросков (`renderDiceHistory`), синхронизация через Firebase для авторизованных, локальная для гостей.
- Быстрые броски D2–D100, кнопка D12, кнопка «Очистить историю».
- Парсер формул `/roll` (`parseRollExpression`): `2d4+3d6-1`, `1d12*2/3`, расшифровка.
- **Бонусы от персонажа**: выбор персонажа, разбивка бонусов по типу броска (`buildRollBonusBreakdown`), авто-подстановка (`applyCharacterBonusIfNeeded`).
- Подсветка критов d12 (Аркана/Попадание).
- **Дублирование броска в Discord** через вебхук из профиля (`sendDiceResultToDiscord`).
- Меню настроек кубов (`loadDiceLocalSettings`), кликабельные результаты/ссылки на заклинания/персонажа.
- **Глобальный перехват ссылок на объекты БД** (`handleDbLinkClick`, `openDbEntity`, `ensureDbModuleLoaded`) — клик по ссылке-заклинанию из любой страницы открывает поп-ап БД.

### 1.7. Редактор персонажей (`character-editor.html`, `character-editor.js` ~4k строк)
- Гейт Google-авторизации, хранение в Firestore `users/{uid}/characters/{id}` через `onSnapshot` (realtime).
- Список персонажей, создание/загрузка/удаление, **экспорт в JSON**, импорт.
- **7 вкладок**: Игровой режим (`tab-main`), Бонусы, Характеристики, Заклинания, Инвентарь, **Рецепты** (`tab-recipes`), Описание.
- Авторасчёт характеристик по уровню (`calculateStatsByLevel`).
- **Редактируемые характеристики** с модалками: инфо по характеристике, бонусы характеристики, ручной ввод/знаковый ввод значения.
- **Бонусы уровня** (отдельный блок) + временные бонусы (модалка добавления).
- Навыки магии/личности (точечная шкала).
- Заклинания: **выбор из БД через модалку с деталями заклинания** (`spell-details`), учебные/фирменные/спонтанные, школы магии через модалку выбора.
- **Рецепты: выбор из БД через модалку** (`recipe-select`), профессии.
- Описание: аккордеон (основное, мировоззрение, внешность, взаимоотношения, прочее).
- Локальный блок бросков кубов завязан на глобальный виджет.

### 1.8. Профиль (`profile.html`, `profile.js`)
- Гейт авторизации, аватар/имя/email из Google.
- Редактирование отображаемого имени.
- **Интеграция Discord**: вебхук URL, имя для бросков, цвет сообщений (палитра свотчей + нативный color picker), тест-сообщение.
- Фиксированная нижняя панель: Сохранить / Сбросить изменения / Выйти (с подтверждением).
- Хранение в Firestore `users/{uid}`.

### 1.9. Лобби (онлайн, BETA) (`lobby.html`, `lobby-room.html`, `lobby.js` ~1.9k строк)
- Гейт Google-авторизации.
- **Создание лобби**, **вход по ссылке/коду приглашения**, список своих лобби.
- Комната: копирование инвайт-ссылки, выход, удаление (владелец), пилюли владельца/участников.
- **Совместный холст рисования** (Firestore realtime): палитра цветов, толщина кисти, **undo/redo**, очистка, **несколько досок/холстов** (вкладки).
- **Чат реального времени** с командой `/roll` (броски в общий поток), пагинация по 100 сообщений, подгрузка истории при прокрутке вверх.

### 1.10. Дашборд (`dashboard.html`, `dashboard.js`)
- Контент-метрики, распределение заклинаний по школам (бары).
- **Аналитика бросков**: метрики по кубам (среднее/ожидаемое/отклонение/криты), статистика по типам бросков, по пользователям, модалка деталей пользователя.
- Качество данных: проблемы по коллекциям, топ правил.
- Источник: `reports/data_report.json` + локальные события кубов.

## 2. Полный список фич НОВОЙ ВЕРСИИ (React)

### 2.1. Каркас (`App.tsx`, `Layout.tsx`, `Sidebar.tsx`)
- HashRouter, маршруты: `/`, `/news`, `/profile`, `/ops`, `/db`, `/character-editor`, `/dashboard`, `/:bookKey/:chapterId`.
- Телеметрия переходов (`page_view`).
- Сайдбар: Главная / Новости / Профиль; Книги (сворачиваемые); Инструменты (Редактор / БД / Дашборд / **Ops Метрики** — только для роли editor); блок аккаунта (вход/выход Google, аватар, роль).
- Кнопка сброса доступа к книгам 🔓 в Layout.
- `AuthProvider` (контекст) + `RequireRole`.

### 2.2. Доступ
- В React `BOOKS`: **только `rumors` locked**, остальные открыты (PHB/Spellbook/Master/Craftbook — `locked: false`).
- ⚠️ Парольная модалка для книг как таковая **не реализована** (есть лишь кнопка сброса флага в Layout).

### 2.3. Книги — `BookPage.tsx`
- Рендер статических HTML-глав из `public/<book>/<chapter>.html`, переписывание legacy-ссылок в SPA-маршруты (`resolveBookLink`).

### 2.4. Новости — `NewsPage.tsx`
- 5 записей из **статического `public/data/news.json`**.
- Секции: Новый функционал (+ ссылки «См. также»), Новые объекты (objectGroups), Статистика.
- ⚠️ Объекты и статистика **«запечены» в JSON-снапшот**, не резолвятся динамически из текущих данных.

### 2.5. База данных — `DbPage.tsx` + `widgets/db-table/*`
- **14 вкладок** (совпадают с legacy), источник — **Firestore** (`status == 'published'`).
- Поиск, сортировка, фильтры (применить/отмена/очистить), персист поиска/фильтров в `sessionStorage`.
- Поп-ап `DetailModal` с **Undo/Redo (Назад/Вперёд)**, URL-состояние `?tab=&detail=`.
- Перекрёстные ссылки в описаниях (`showSpellPage`/`showSchoolPage`/… → навигация), родительские/под-заклинания, связанные школы (`resolveByName`).
- Подробные верстки для: spells, schools, effects, actions, skills, recipes; **остальные типы — `GenericDetail` (только имя+описание)**.
- `SpellRollFooter`: кнопки Аркана/Попадание/Наложение — **локальный `Math.random()` d20**, без истории/Discord/виджета.

### 2.6. Редактор персонажей — `CharacterEditorPage.tsx`
- Гейт Google-авторизации (+ гостевой тест-режим через localStorage), хранение Firestore `users/{uid}/characters`.
- Список, создание/загрузка/удаление/**экспорт JSON**/импорт (в тест-режиме).
- **7 вкладок**: Игровой режим, Бонусы, Характеристики, Заклинания, Инвентарь, **Ремесло**, Описание.
- Авторасчёт характеристик, навыки (точечная шкала), временные бонусы.
- Локальный **DiceRoller** (Аркана/Попадание/Наложение d12 + кастомный бросок) — пишет события в `localStorage` (`diceRollEventsLegacy`).

### 2.7. Профиль — `ProfilePage.tsx`
- Аватар/имя/email, редактирование имени.
- Интеграция Discord: вебхук, имя, цвет (свотчи + color picker), тест-сообщение. Хранение Firestore `users/{uid}`.

### 2.8. Дашборд — `DashboardPage.tsx`
- Полный паритет с legacy: контент, аналитика бросков (кубы/типы/пользователи + модалка), качество данных. Источник `reports/data_report.json` + локальные события.

### 2.9. Ops — `OpsPage.tsx`
- **Новая фича, которой нет в legacy** (метрики для роли editor).

## 3. ПРОБЕЛЫ: чего не хватает / что неполно в React

### 3.1. Критичные (отсутствует целиком)
1. **ЛОББИ — полностью отсутствует.** Нет маршрута, страницы, ссылки в сайдбаре/на главной. Самый крупный недостающий модуль: комнаты, инвайты, realtime-чат с `/roll`, совместный холст с досками и undo/redo.
2. **Глобальный плавающий виджет кубов** — отсутствует. В React броски только внутри редактора и они примитивны:
   - нет истории бросков и её синхронизации (Firebase/локально);
   - нет быстрых бросков D2–D100, нет парсера сложных формул `/roll`;
   - нет разбивки бонусов от выбранного персонажа;
   - **нет отправки бросков в Discord** (хотя профиль вебхук настраивает — фича висит «вхолостую»);
   - нет подсветки критов; роллы используют `Math.random()` вместо общего движка.
3. **Кликабельные формулы бросков** в описаниях БД/редактора — не реализованы (legacy `linkifyDiceExpressions`).
4. **Глобальный перехват ссылок на объекты БД** с любой страницы — не реализован (в React работает только внутри поп-апа).

### 3.2. Парольная защита книг
5. В legacy книги закрыты паролем (`access.js` модалка). В React модалки нет, а `locked` стоит лишь у `rumors` (и не приводит к запросу пароля). Нужно решить: переносим парольный гейт или осознанно отказываемся.

### 3.3. Новости — неполнота
6. **Динамическое разрешение «Новых объектов» и статистики** заменено статическим снапшотом в `news.json`. Соответствует жалобе «отображается только новый функционал, а не весь список»: при добавлении контента списки в новостях не обновятся; для свежих записей objectGroups пустые. Нужно либо генерировать `news.json` из данных, либо резолвить на лету (как legacy).

### 3.4. База данных — частичные потери
7. **Generic-поп-ап** для action-types, combat, craft-components/professions/specializations, recipe-types, basics, archetypes — теряет структурированные поля (показывает только имя+описание). В legacy у них своя верстка/саммари.
8. Авто-кнопки бросков в поп-апе заклинаний есть, но **не интегрированы с виджетом/историей/Discord** (см. 3.1.2).

### 3.5. Редактор персонажей — упрощения
9. **Вкладка «Рецепты» с выбором из БД** (модалка `recipe-select`) → в React заменена на **свободный текст «Ремесло»**. Потеря структурированного выбора рецептов/профессий.
10. **Заклинания из БД через модалку с деталями** → в React простой `<select>` по имени (нет предпросмотра деталей заклинания при выборе).
11. **Редактируемые характеристики с модалками** (ручной ввод, бонусы характеристики, инфо) → в React характеристики только расчётные/read-only + отдельные поля ресурсов.
12. **Бонусы уровня** отдельным блоком — в React отсутствуют (есть только временные бонусы).
13. Realtime (`onSnapshot`) персонажей в legacy → в React **разовая загрузка `getDocs`** (`CharacterRepository`). Список не обновляется на лету при изменениях с другого устройства/вкладки.

### 3.6. Мелочи
14. **Кнопка «Наверх»** — в legacy на всех страницах; в React глобальной кнопки нет (scroll-to-top логика есть только внутри `BookPage` при смене главы).
15. Ссылка/карточка **«Лобби»** на главной и в сайдбаре отсутствует (следствие 3.1.1).
16. Главная: в legacy секции «Книги (Доступные/На тестировании 🔒)» и «Инструменты (вкл. Лобби, Дашборд)»; в React — «Разделы» (БД/Редактор/Новости/Профиль) + «Книги правил». Состав карточек разошёлся.

## 4. Представление данных: где и в каком виде (сравнение)

| Данные | Legacy: где / форма | React: где / форма | Расхождение / косяк |
|---|---|---|---|
| Компендиум (14 коллекций) | Локальные `data/*.json`, fetch по `getDataUrl()` | **Firestore**, `where status == 'published'` (`CompendiumRepository`) | Разные источники истины. `data/*.json` и Firestore надо держать синхронными; legacy не видит правок, сделанных только в Firestore, и наоборот. |
| Новости | `data/*.json` + код `news.js` (динамический резолв) | Статический `public/data/news.json` (снапшот) | React-новости не обновляются при росте контента (см. 3.3.6). |
| Книги/главы | HTML-файлы в `phb/`, `spellbook/`, … | Те же HTML в `public/<book>/` | Паритет (контент копируется). Ссылки переписываются `resolveBookLink`. |
| Персонажи | Firestore `users/{uid}/characters/{id}`, realtime `onSnapshot` | Firestore `users/{uid}/characters` (через `CharacterRepository`) | Один и тот же путь ✅. Проверить realtime vs разовая загрузка. |
| Профиль (имя, Discord webhook/имя/цвет) | Firestore `users/{uid}` | Firestore `users/{uid}` (`displayName`, `discordWebhookUrl`, `discordDisplayName`, `discordColor`) | Паритет ✅. |
| Доступ к книгам (пароль) | `localStorage[PASSWORD_KEY]` + модалка | `localStorage[PASSWORD_KEY]` (только сброс, без модалки) | Гейта ввода пароля нет (см. 3.2.5). |
| События кубов (для дашборда) | `localStorage` (`diceRollEventsLegacy`) + синхронизация Firebase; снапшот `data/dice_roll_events.json`; отчёт `reports/data_report.json` | Только `localStorage` (`diceRollEventsLegacy`), формат событий совместим | React **не пишет броски в Firebase** → межпользовательская аналитика дашборда не увидит React-роллы. |
| История бросков виджета | `localStorage` + Firebase (для авторизованных) | — (виджета нет) | Отсутствует (см. 3.1.2). |
| Лобби (комнаты/чат/холст) | Firestore (realtime) | — | Отсутствует (см. 3.1.1). |
| Манифест контента | — | Firestore `contentManifest/{env}` (`ContentRepository.getManifest`) | Новая инфраструктура версионирования (нет в legacy). |
| Дашборд-отчёт | `reports/data_report.json` | `reports/data_report.json` | Паритет ✅. |

## 5. РЕШЕНИЯ (2026-06-03)

- **Лобби — НЕ переносим** (вне области).
- **Виджет кубов — полный глобальный** (история+синк, /roll, бонусы персонажа, Discord, кликабельные формулы, криты).
- **Пароль книг — гейтим только `rumors`** сейчас; обёртку делаем переиспользуемой.
- **Редактор — полный фиделити + улучшения** (не тупой 1:1).
- **Сквозные ссылки — оверлей-попап** поверх текущей страницы.
- **Крафт-трекинг прогресса — НЕ делаем.**
- **Броски пишем в Firestore + чиним дашборд — делаем.**

## 6. План реализации (фазы)

Источник: `apps/web/src` (symlink `node_modules/@e-magios/web`). Не редактируем через node_modules.
